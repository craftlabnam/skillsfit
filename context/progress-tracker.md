- **`library-docs.md` OpenAI GPT-4o section corrected — profile extraction crashed on `JSON.parse`.** Feature 07's extraction call followed the documented pattern: `800` `max_tokens` and a bare `JSON.parse(response.choices[0].message.content!)` with no truncation check. A real resume's full profile does not fit in `800` output tokens, so the response was cut off mid-value and `JSON.parse` threw ("Unterminated string in JSON", "Expected double-quoted property name"). The guidance shipped the crash to every future implementation. Three fixes to `library-docs.md`: (1) raised the profile-extraction cap from `800` to `4000`; (2) added a `finish_reason === "length"` guard before every `JSON.parse` — the generic pattern throws, and the new Profile Extraction pattern surfaces a typed `ResumeTooLongError` the UI can show as "resume too long, try a shorter file"; (3) moved profile extraction from `json_object` to a strict `json_schema` response format so the returned shape is deterministic and maps straight onto the profile form fields. No application code changed — Feature 07 is not built yet, so this is a guidance fix that stops the crash before it reaches real users.
